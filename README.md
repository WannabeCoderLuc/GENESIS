# Universe Creator: Genesis

This folder is the **primary development environment and repository root** for Universe Creator: Genesis—not a concept archive. It contains the product specification now and will contain the Roblox source tree, tests, tooling, generated-asset manifests, audit evidence, and release configuration as implementation proceeds.

The project is an AI-first, PC-only Roblox cosmic sandbox, incremental strategy game, exploration experience, and light MMO.

## Product promise

The player creates a persistent pocket universe, beginning with a single star and graduating through planetary systems, galaxies, clusters, the cosmic web, and successive cosmic epochs. Progress changes the scale and nature of play instead of merely increasing numbers. Home universes remain safe; social visits, cooperative events, ranked optimization challenges, and an optional risk zone provide multiplayer depth.

## Non-negotiables

- Built entirely by AI agents using Roblox Studio, Luau, Roblox-native services, project-owned generated assets, and approved native generation/editing APIs.
- No externally sourced production models, textures, sounds, UI kits, or code of uncertain provenance.
- PC-only controls and presentation; readable and inviting to younger players, strategically satisfying to older players.
- Server-authoritative progression and economy.
- Deterministic seeded generation: save intent, seeds, decisions, and deltas—not billions of objects.
- Continuous-scale illusion through representation changes, LOD, impostors, streaming, and floating origins.
- Minor, ethical monetization: cosmetic and convenience-oriented, never pay-to-win.
- Horus-main is integrated through a pinned project adapter and review gates; the source repository is not modified by default.

## Tooling

Installed and hash-pinned in `tools/bin/` (git-ignored): **Rojo 7.7.1** and **Selene 0.32.0**. Node 22 runs the zero-dependency
repository tools. Roblox Studio (through the `Roblox_Studio` MCP server) is the Luau runtime for tests. The type-checker
and formatter gates are **pending** until their tools are approved. Everything, including commands and gate status, is in
[`docs/TOOLCHAIN.md`](docs/TOOLCHAIN.md).

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/bootstrap/install-tools.ps1   # Rojo + Selene
tools/bin/selene.exe src tests
npm run lint:policy && npm run check:vectors && npm run test:tools
```

1. Read `AGENTS.md`, `00-CONCEPT.md`, `03-ARCHITECTURE.md`, and the phase currently assigned.
2. Read `roblox_skills_guide.md`, discover the active Roblox Studio MCP server, and verify which `rbx-*` skills and Studio operations are actually available before invoking them.
3. Create the repository skeleton and a minimal Rojo/Studio sync path if the chosen agent environment supports it.
4. Build Phase 0 contracts and deterministic tests before visual production.
5. Complete the First Star vertical slice before expanding scope.
6. Run the security, performance, data, and visual gates at every milestone.

## Roblox Studio MCP and custom skills

Roblox implementation agents should use the Roblox Studio MCP server for direct Studio inspection, controlled edits, playtests, multi-client validation, debugging, documentation lookup, scene analysis, MicroProfiler capture, and heap investigation whenever the corresponding capability is present. Built-in `rbx-*` skills are loaded on demand; their names and expected uses are summarized in `roblox_skills_guide.md`. Never assume a skill or API exists merely because the guide mentions it—discover and verify it in the active Studio session first, and record a manual fallback when it is unavailable.

Create a project-scoped custom skill under `.agents/skills/<skill-name>/SKILL.md` when a workflow is repeated, project-specific, safety-sensitive, or easy for autonomous agents to execute inconsistently. Good candidates include deterministic-generation regression capture, Horus audits, published teleport smoke tests, visual baseline capture, asset-manifest validation, and release qualification. Do not create a custom skill for a one-off task or duplicate a built-in `rbx-*` skill. Follow the frontmatter, progressive-disclosure, scripts, and references conventions in `roblox_skills_guide.md`.
